# API del portal para Digui — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three JSON routes on `mi.zardelfitness.com.ar/api/digui/` (free slots, a client's appointments, request an appointment) plus a plain-text docs route, called by Digui's server with a secret key.

**Architecture:** Pure helpers (key check, phone tail, input parsing, messages) in `portal/lib/digui-api.ts`, unit-tested with `node --test`. Server-side data access in `portal/lib/turnos.ts`, which also takes over the booking rules from `portal/agenda-actions.ts` so the portal and the API share them. Thin route handlers under `app/(portal)/portal/api/digui/`, reached without Clerk through `proxy.ts`.

**Tech Stack:** Next.js App Router route handlers, TypeScript, `pg`, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-05-digui-api-design.md`

## Global Constraints

- Routes (host `mi.zardelfitness.com.ar`): `GET /api/digui` (docs, no key), `GET /api/digui/horarios?dia=AAAA-MM-DD`, `GET /api/digui/turnos?telefono=…|customer_id=…`, `POST /api/digui/turnos` with JSON `{"inicio": "AAAA-MM-DDTHH:MM", "telefono": "…"}` or `customer_id`.
- Responses `200`: `{"ok": true, "horarios": ["16:00", …], "mensaje"}`, `{"ok": true, "turnos": [{"dia", "hora", "estado": "pedido"|"confirmado"}], "mensaje"}`, `{"ok": true|false, "mensaje"}`. Business outcomes are `200` with `"ok": false` and a `mensaje`. HTTP errors only: `401` (key), `400` (unreadable input).
- Key: env `DIGUI_API_KEY`, header `Authorization: Bearer <key>`, constant-time compare. Env unset → every keyed route answers `401`.
- Identity, filled by Digui's server: `customer_id` (a `users.id` with `role = 'user'`) or `telefono` (last 7 digits equal to exactly one client's `users.phone`, `role = 'user'`). Both given → `customer_id` wins. Fewer than 7 digits → no match. Coaches and admins never match.
- `active` and `pass_expires` don't stop a request (same as the portal).
- Booking rules = the portal's: one live (`requested`/`confirmed`) future appointment per client, start must be one of `freeSlots` of its day (portal appointments + Google busy; `busy()` null counts as nothing busy), unique index race → its message. The API also requires the day to be in `bookableDays(todayISO(), HOURS)`.
- Times are Argentina (`-03:00`); `inicio` without an offset is Argentina time.
- Exact copy (Spanish), reused from `agenda-actions.ts` where it exists:
  - `"Ya tenés un turno pedido. Si querés otro horario, cancelalo primero."`
  - `"Ese horario ya no está libre: elegí otro."`
  - `"Justo lo pidió otra persona: elegí otro horario."`
  - `` `Pedido: ${longDate(dia)} a las ${hora} h. Te avisamos cuando esté confirmado.` ``
  - `"No encontramos tu ficha con este número: pedí el turno desde el portal o escribile al Zar."` (telefono) / `"No encontramos tu ficha: pedí el turno desde el portal o escribile al Zar."` (customer_id)
  - `"Ese día no se puede pedir: elegí uno entre mañana y los próximos 30 días en que abre el gimnasio."`
- The portal's own behavior must not change (its pages and actions, including that it doesn't check `DAYS_AHEAD` on request).

## Review Focus

1. A start that isn't on the slot grid (16:10), is within 12 h, or is on a closed day → `ok: false` with a message, never an insert. Test in Task 3 (curl).
2. Two clients whose phones share the last 7 digits → no match for either (nobody books as the wrong person). Test in Task 2's query and Task 3 (curl with two seeded clients).
3. `customer_id` sent as a string (`"12"`) or a number (`12`) → both accepted; `"12abc"`, `0`, negatives → 400. Test in Task 1.
4. `inicio` without offset is Argentina time, not the server's UTC: `"2026-11-06T16:30"` → `2026-11-06T19:30:00.000Z`. Test in Task 1.
5. A request on the `mi.` host with an `Authorization: Bearer` header reaches the route without Clerk touching it, and `GET /api/digui` works without a key. Test in Task 3 (curl).

### Task 1: Pure helpers

**Files:**
- Create: `site/portal/lib/digui-api.ts` (no `server-only`, no `db` import: testable with `node --test`)
- Create: `site/portal/lib/digui-api.test.ts`

**Interfaces:**
- Produces:
  - `keyOk(header: string | null, key: string | undefined): boolean` — `false` when `key` is empty/undefined; compares `Bearer <key>` in constant time (hash both sides, `timingSafeEqual`).
  - `phoneTail(phone: string | null | undefined): string | null` — last 7 digits, or `null` with fewer than 7.
  - `customerId(v: unknown): number | null` — a positive integer from a number or an all-digits string; else `null`.
  - `parseDay(v: string | null): string | null` — `"AAAA-MM-DD"` that is a real date, else `null`.
  - `parseStart(v: unknown): Date | null` — `"AAAA-MM-DDTHH:MM"` as Argentina time (reuse `fromLocalInput` from `./format.ts`), else `null`.
  - `NO_FILE_PHONE`, `NO_FILE_ID`, `BAD_DAY` — the three new messages from Global Constraints.

  assert.equal(keyOk("Bearer ", ""), false);
  assert.equal(keyOk("Bearer x", undefined), false);

test("el teléfono: los últimos 7 dígitos, con o sin 9, 0 y 15", () => {

  assert.equal(phoneTail("0351 15 555-1234"), phoneTail("+54 9 351 555-1234"));

test("customer_id: entero positivo, como número o texto", () => {

  for (const d of [null, "", "2026-13-01", "2026-02-30", "06/11/2026", "2026-11-6"]) assert.equal(parseDay(d), null, String(d));
  assert.equal(parseStart("2026-11-06T16:30")?.toISOString(), "2026-11-06T19:30:00.000Z");

### Task 2: Shared booking rules and the API's queries

**Files:**
- Create: `site/portal/lib/turnos.ts` (`import "server-only"`)
- Modify: `site/portal/agenda-actions.ts` (`slotError` and the body of `requestAppointment` move to `turnos.ts`; `requestAppointment` keeps `requireViewer`, the role check, `refresh()` and its return shape)

**Interfaces:**
- Consumes: `phoneTail`, `NO_FILE_PHONE`, `NO_FILE_ID` (Task 1); `freeSlots`, `bookableDays`, `hoursFrom`, `SLOT_MINUTES` (`./slots`); `takenIntervals` (`./data`); `busy` (`./google`); `dateOf`, `timeOf`, `longDate`, `todayISO` (`./format`).
- Produces:
  - `slotError(start: Date, exceptId?: number | null): Promise<string | null>` (moved as is; `agenda-actions.ts`'s other callers import it from here)
  - `requestSlot(clientId: number, start: Date): Promise<{ ok: true; mensaje: string } | { ok: false; mensaje: string }>` — exactly `requestAppointment`'s rules and messages (live appointment, `slotError`, insert with `created_by = clientId`, `23505`).
  - `clientByPhone(phone: string): Promise<number | null>` — the single `role = 'user'` whose `phoneTail(users.phone)` equals `phoneTail(phone)`; `null` for none or several.

  - `liveAppointments(clientId: number): Promise<{ dia: string; hora: string; estado: "pedido" | "confirmado" }[]>` — `requested`/`confirmed`, `ends_at > now()`, by `starts_at`.

### Task 3: The routes and the Clerk bypass

**Files:**
- Create: `site/app/(portal)/portal/api/digui/route.ts` (`GET`: the docs, `text/plain; charset=utf-8`, no key)
- Create: `site/app/(portal)/portal/api/digui/horarios/route.ts` (`GET`)
- Create: `site/app/(portal)/portal/api/digui/turnos/route.ts` (`GET`, `POST`)
- Modify: `site/proxy.ts` (on the portal host, `/api/digui` and `/api/digui/…` are rewritten to `/portal/api/digui…` without `clerk`)
- Modify: `site/README.md` (Portal section: `DIGUI_API_KEY`, what the API is for, the docs link)

**Interfaces:**
- Consumes: Task 1's helpers and messages; Task 2's `requestSlot`, `clientByPhone`, `clientById`, `liveAppointments`, `freeTimes`; `bookableDays`, `HOURS`, `todayISO`, `longDate`.

Behavior:
- Keyed routes start with `keyOk(req.headers.get("authorization"), process.env.DIGUI_API_KEY)` → else `401` `{"ok": false, "mensaje": "Clave equivocada."}`. All routes `export const dynamic = "force-dynamic"`.
- `horarios`: bad/missing `dia` → `400` `{"ok": false, "mensaje": "La fecha va como AAAA-MM-DD."}`; not in `bookableDays(todayISO(), HOURS)` → `200` `BAD_DAY`; else `freeTimes(dia)` with `mensaje` `` `Horarios libres el ${longDate(dia)}: ${list}.` `` or `` `No quedan horarios libres el ${longDate(dia)}.` ``.
- `turnos` identity (query for GET, JSON body for POST): `customerId(customer_id)` → `clientById`; else `telefono` → `clientByPhone`; neither present/readable → `400` `{"ok": false, "mensaje": "Falta el teléfono o el customer_id."}`; no client → `200` `ok: false` with `NO_FILE_ID` or `NO_FILE_PHONE`.
- `GET turnos`: `liveAppointments` with `mensaje` `"No tenés turnos pedidos ni confirmados."` or one line per turno `` `${longDate(dia)} a las ${hora} h (${estado}).` `` joined by spaces.
- `POST turnos`: unreadable JSON → `400` `{"ok": false, "mensaje": "El cuerpo va en JSON."}`; bad `inicio` → `400` `{"ok": false, "mensaje": "El inicio va como AAAA-MM-DDTHH:MM."}`; day of `inicio` not bookable → `200` `BAD_DAY`; else `requestSlot(clientId, start)`.
- Docs text (Spanish): base URL, the header, each route with its inputs and response shapes, that `telefono`/`customer_id` are who the person is and must come from Digui's server, that times are Argentina's, and the `ok: false` convention. No secrets.
